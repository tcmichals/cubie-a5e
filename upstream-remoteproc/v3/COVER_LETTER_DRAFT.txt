Subject: [PATCH v3 0/7] Add Allwinner A523 message box and XuanTie E906 remoteproc support

This series adds a driver for the message box of the Allwinner A523,
A527 and T527 (sun55i) and a remoteproc driver for their T-Head XuanTie
E906 RISC-V core, with bindings, DT nodes and KUnit tests.

v2: https://lore.kernel.org/linux-sunxi/20260927002021.797069-1-tcmichals@gmail.com/

Changes in v3 (details in each patch):
  - Message box: all four banks are clocked and out of reset (an
    unclocked bank drops writes). The FIFO is drained before its pending
    bit is cleared. A kick is done once the receiver's FIFO has room;
    allwinner,tx-done-irq selects the receiver bank's write interrupt
    instead of the 1 ms poll, like ti,mbox-send-noirq does for OMAP.
  - Remoteproc: one mailbox channel; the receive callback is deferred to
    an ordered workqueue; address translation covers only the two SRAM
    windows; debug reset and power domains added; all resources are
    required.
  - Bindings: fixed lists for reg, clocks, resets, interrupts and
    memory-region; "schema" dropped from the subjects (Krzysztof).
  - KUnit patches moved after the drivers. The message box tests run
    against a mock that models the FIFOs and status registers.
  - Rebased on next-20261020.

Notes for review:
  - The remap register (0x07010364, PRCM) is shared with the DSP: bit 1
    hands SRAM A3_2 (SRAM space 1) to the E906, bit 0 belongs to the
    DSP. The driver maps only this register and read-modify-writes
    bit 1, which is safe while no other Linux driver writes it. I can
    move it to a syscon or the R-CCU if preferred.
  - memory-region index 0 is the virtio DMA pool, then dram and trace,
    as in the TI K3 and MediaTek SCP bindings.
  - The optional crash interrupt is supported by the driver but not
    wired in any DT and not tested; the vendor BSP has none.

Testing on a Radxa Cubie A5E (A527), Linux 7.1 PREEMPT_RT with the same
driver and test files:
  - KUnit: 24/24 message box, 15/15 remoteproc. The message box tests
    also pass under UML on x86_64.
  - rpmsg ping (10000 messages, about 165 us round trip) and stress
    (100000 messages, 16 in flight, no loss), with vrings in DRAM and in
    SRAM, TX done by poll and by write interrupt, and message box
    unbind/bind. One interrupt per message.
  - A non-RT kernel with DEBUG_ATOMIC_SLEEP and PROVE_LOCKING showed no
    warnings from these drivers (run before the message box drain and TX
    completion changes; the board tests above cover those).
  - On next-20261020: W=1 build, dt_binding_check, dtbs_check and
    checkpatch --strict are clean.
