## Gemini Pro Review (Single-File Bundle)

Gemini Pro on the web cannot open files or run tools, so it only knows what is in the
one file you attach. `scripts/make_audit_bundle.py` builds that file from git, so it
always matches the commit being reviewed.

### What goes into the bundle

| Part | Content | Source |
|---|---|---|
| 1 | Review protocol: stages S0–S8 and the required output format | `scripts/prompts/review/protocol.md` |
| 2 | Cover letter (as claims to verify) + `git format-patch` of the series | latest `v<N>/*0000-cover-letter.patch`, linux-cubie git |
| 3 | Sashiko guides + **every** `scripts/prompts/subsystem/*.md` | `~/.local/share/sashiko/prompts/*/kernel`, this repo |
| 4 | Every file the series touches, full and line-numbered (for `path:line` citations) | linux-cubie at `--ref` |
| 5 | Framework contracts: mailbox core, remoteproc core/virtio, IRQ helpers, memremap, reference drivers, DT schema docs, dt-bindings headers | linux-cubie at `--ref` |
| 6 | Tool output: `checkpatch --strict`, `yamllint`, `dt-doc-validate`, `make dt_binding_check` (optional `--dtbs-check`) | run locally |
| 7 | Prior review comments for the S0 regression matrix | `v*/COMMENTS.md` |

The series range is auto-detected: commits are walked back from `--ref` while they touch
the sun55i msgbox/rproc paths. `REVIEW_ANSWER_KEY.md` is **never** embedded.

### Generate and run

```bash
cd cubie-a5e/upstream-remoteproc
python3 scripts/make_audit_bundle.py            # -> GEMINI_PRO_AUDIT_BUNDLE.md (~200k tokens, ~40 s)
```

1. Open Gemini, select the **Pro** model, start a **new** chat.
2. Attach `GEMINI_PRO_AUDIT_BUNDLE.md` and send: `Follow Part 1 of the attached file.`
3. Save the full reply as `v<N>/GEMINI_REVIEW.md`.
4. If the reply has a `NEEDS_CONTEXT` list, add those files and regenerate:
   `python3 scripts/make_audit_bundle.py --extra kernel/time/hrtimer.c:hrtimer_cancel --extra drivers/base/dd.c`
   (`path` embeds the whole file; `path:fn1,fn2` embeds only those functions.)
5. Check every finding against the code yourself. Gemini's verdict is input to your review, not the final word.

### Benchmark a prompt change (blind mode)

`--blind` leaves out the prior comments (Part 7) and the local subsystem guides, because
they name the known bugs. Use it to measure whether a protocol change actually finds more:

```bash
python3 scripts/make_audit_bundle.py --blind -o /tmp/blind_bundle.md
# run it in Gemini, save the reply, then:
python3 scripts/score_review.py v3/GEMINI_BLIND_REVIEW.md
```

### Adding or changing review rules

* **Protocol, stages or output format:** edit `scripts/prompts/review/protocol.md`.
* **New project rules or invariants:** add a `.md` file to `scripts/prompts/subsystem/`.
  It is picked up automatically, so no script change is needed.
* **More framework or reference code:** add it to `CONTEXT` in `make_audit_bundle.py`
  (permanent) or pass `--extra` (one-off).
* State **properties to check**, not expected answers ("who owns the pointer passed to
  `mbox_send_message()`?", not "verify the message is on the stack"). Rules written as
  answers are how the old hand-written bundle ended up telling the reviewer the wrong fix.

## Setting Up Sashiko Local Review Tool on Any Machine

Sashiko is the Linux Foundation AI review tool used by `sashiko-bot@kernel.org` on `lore.kernel.org`. You can run it locally to review your commits before submitting patches to the mailing list.

> [!IMPORTANT]
> **Do NOT use `sudo apt install cargo`**. Ubuntu's packaged Rust (1.75) is too old and fails with `feature edition2024 is required`. Always install modern Rust via `rustup`.

### Step 1: Install Modern Rust via `rustup`
```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
source "$HOME/.cargo/env"
```

### Step 2: Install Sashiko CLI
```bash
cargo install sashiko
```

### Step 3: Initialize Configuration & Download Official Prompts
```bash
sashiko init
```
* This writes `~/.config/sashiko.toml` and installs all official Linux kernel subsystem review prompts to `~/.local/share/sashiko/prompts/.../kernel/`.

### Step 4: Run Review on Local Commits
```bash
# Set your LLM API Key (Gemini, Claude, OpenAI, Bedrock, etc.)
export GEMINI_API_KEY="your-key-here"

# Review the 7 commits of your RemoteProc & Mailbox series:
cd /path/to/linux-cubie
sashiko review HEAD~7..HEAD

# Or validate patch extraction without spending API credits:
sashiko review --no-ai HEAD~7..HEAD
```
